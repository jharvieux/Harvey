How an engagement works

  1. Intake

    Fill in the form below — about fifteen minutes. We reply within one business day with scope, a fixed quote, and the kickoff checklist.

  2. Access

    You grant the short access list described below. Credentials and tokens are exchanged over a secure channel we set up at kickoff — never through this form, never by plain email.

  3. Audit

    The audit runs against a local, access-controlled checkout of your repository. Your code never leaves the engagement machine, and we never touch production credentials. Dynamic testing runs against a seeded local stack or your staging environment only.

  4. Report & remediation

    You receive a severity-ranked findings report with evidence for every claim, a "checked and ruled out" section so you know what was verified clean, and a prioritized action plan. Optionally, we deliver fixes as reviewable pull requests.

What we'll ask you for

  • 1. Repository read access

    A collaborator invite with read permission (or a zip export if you prefer). We clone once to the engagement machine.

  • 2. A fine-grained GitHub token

    Scoped to the single repository under audit: contents: read. If you purchase fix delivery, additionally pull_requests: write so fixes arrive as PRs you review. Nothing broader.

  • 3. A read-only database connection

    A read-only Supabase connection string. It drives the data-classification pass (what PII/PHI/payment data actually lives where) and database configuration checks. Read-only is verified before use.

  • 4. A staging environment (optional)

    For dynamic penetration testing of tenant isolation. If you don't have one, we run those probes against a locally seeded copy of your stack instead. We never test against production.

  • 5. Fifteen minutes of answers

    The questionnaire in the intake form below — the handful of facts we can't detect from code, like your intended tenancy model and compliance context. Everything detectable, we detect rather than ask.

How we handle your data

  • No code egress. Your repository is audited on a local, access-controlled machine. It is not uploaded to third-party services.
  • Least privilege, always. Read-only access everywhere except optional PR delivery. We never hold production credentials — that's a hard rule, not a preference.
  • Secrets out-of-band. Tokens and connection strings move over a secure channel established at kickoff. This form has no fields for them by design; please don't put credentials in any free-text box.
  • Purge at close. When the engagement ends, access is revoked, and the checkout and all scan artifacts are destroyed. We retain the delivered report and the engagement record.
