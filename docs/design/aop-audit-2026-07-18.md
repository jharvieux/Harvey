# AoP — full ten-module Harvey audit (engagement 2026-07-18)

**Target:** Age of Plunder (`AoP`) — a pirate strategy game. pnpm monorepo, TypeScript.
Vite/React SPA at `apps/web/` (PixiJS renderer), Supabase backend (30 migrations +
~30 Deno Edge Functions), shared packages (`@aop/engine`, `@aop/content`, `@aop/shared`, tools).
**Findings repo:** `jharvieux/AoP` (public). **Live Supabase project:** `udsuxdoavlvosvbjwmud` (read-only).

**Headline:** AoP has a **genuinely strong security posture** — no High/Critical confirmed
vulnerabilities. The team has already fixed the classic Supabase multi-tenant bugs (RLS-recursion
IDOR `#334`, active-match seed leak `#135`, `user_match_ids` argument-spoofing IDOR). Authority is
correctly centralized in service-role Edge Functions; every game-state write bypasses RLS by design
and every client-facing table is deny-all or own-row. What remains is a tail of **Low/Medium
hardening, performance, and code-health items** — 16 filed. This is a healthy report, not a scary one.

### Triaged OUT (false positives / intentional — NOT filed, per fp-rules)

- **2× `verify_jwt = false` Edge Functions** (`stripe-webhook`, `compact-snapshots`) — both authenticate
  internally (Stripe HMAC signature; `Authorization: Bearer <CRON_SECRET>`). Correct, not findings.
- **`community_maps` / `community_map_reports` RLS-enabled-no-policy** — intentional deny-all
  (edge-function-only authority, same pattern as `match_snapshots`); clients never SELECT them directly.
- **`match_seed(uuid)` / `user_match_ids()` SECURITY DEFINER "review" flags** — both correctly guard the
  caller (seat + finished-status / `auth.uid()` with no spoofable arg). No change needed.
- **12 mechanical "RLS policy / SECURITY DEFINER — semantic review" High flags** — these are review
  *queue* items, not confirmed vulns; every one triaged (service_role-only grants, or guarded).
- **18 M9 "SSR-only API misuse" + 8 "next/image" (root scan)** — Vite SPA false-fires; 0 on the correct
  per-app scan. Harvey gap `#597`.
- **gitleaks "2 leaks"** — the local, git-ignored `.env.local` (never committed; `git ls-files` confirms
  untracked). TruffleHog verified 0. No secret-in-repo finding.
- **"First-load JS over budget (Vite)"** — the app already ships `asset-size-allowlist.json` + a vite
  `assetBudget` plugin; PixiJS (~538 KB) inherently dominates a WebGL game bundle. Accepted tradeoff, noted.
- **Open signup / email confirmation disabled** — folded into the security narrative as product-context
  config (guest-first game); email-confirmation-off is worth a deliberate decision but not a vuln.

## Semantic → mechanical & harness gaps filed in `jharvieux/Harvey`

- **[#597](https://github.com/jharvieux/Harvey/issues/597)** (M9 precision) — the framework probe is
  **not monorepo-aware**: at a monorepo root `detectTargetFramework` returns `other`, so the M9 SSR
  suppression #575 added never engages and the Vite false-fires return. Reproduced this engagement:
  root scan → 17 SSR FPs; `apps/web` scan → 0.
- **[#598](https://github.com/jharvieux/Harvey/issues/598)** (M2 harness) — the generic two-tenant seed
  does a plain `INSERT` into `profiles`, colliding with a `handle_new_user` auth trigger (a very common
  Supabase pattern), and mislabels the seed failure as `M2-PROVISION-MIGRATE` ("migrations don't apply
  cleanly") when the migrations in fact applied.

## Notes for the operator

- **#159 NO-RATE-LIMIT probe:** AoP does expose high-value flow routes (`create-checkout-session`,
  matchmaking, `send-chat`), but because M2's cross-tenant matrix didn't run (harness seed collision,
  `#598`), the rate-limit probe was **not exercised** this engagement. AoP is a strong future target for
  it once `#598` lands.
- **Teardown confirmed:** all M2 local Docker infra stopped — `docker ps -aq` returns 0. The live hosted
  DB was never touched by writes (local stack ≠ hosted project).
- Both checkouts left clean (read-only static scan of the AoP checkout; primary Harvey checkout untouched).

## Bottom line

AoP is a well-secured, well-tested pre-launch app. The audit's value here is the **honest tail**: a
Medium dependency CVE (`qs`), a batch of RLS/CI/supply-chain hardening, real N+1s in the cron/push
Edge Functions, a catalog triplication, and 26 stub-surviving tests (notably around save/load, which
overlaps the team's active save-durability work `#539`/`#540`). No module was silently skipped: M2 and
M3 are recorded partial with their reasons; M9 is a correct N/A.
